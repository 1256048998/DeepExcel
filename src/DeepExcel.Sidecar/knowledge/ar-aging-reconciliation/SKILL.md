# 应收账龄与对账

## 一、先确认

1. **截止日**：放在一个参数单元格里，所有账龄都按它算，不用 `TODAY()`。
2. **账龄起算日**：按开票日、按业务发生日，还是按到期日（逾期账龄）——三种结果不同，问清楚。
3. **账龄分段**：公司制度通常规定好了，例如 0–30 天、31–60 天、61–90 天、91–180 天、181–365 天、1–2 年、2–3 年、3 年以上。
4. **回款怎么核销**：先进先出（冲最早的发票），还是按回款时指定的发票。

## 二、账龄分段

分段点放参数表，用 LOOKUP 而不是一长串嵌套 IF：

```
天数：=$截止日$-起算日
分段：=LOOKUP(天数,{0,31,61,91,181,366,731,1096},{"0-30天","31-60天","61-90天","91-180天","181-365天","1-2年","2-3年","3年以上"})
```

天数为负（起算日晚于截止日）的是未来的单据，单独列出，不要归进 0–30 天。

## 三、先进先出核销

同一客户的发票按日期升序排好（sort_data：先客户、再日期）。每张发票的未核销余额：

```
截至本张的累计开票 = SUMIFS(金额, 客户, 本行客户, 日期, "<="&本行日期)   （同日多张时改用行号累计）
客户回款合计       = SUMIFS(回款表!金额, 回款表!客户, 本行客户, 回款表!日期, "<="&截止日)
未核销余额         = MIN(本张金额, MAX(0, 截至本张的累计开票 − 客户回款合计))
```

- 检查：每个客户「未核销余额之和 = 开票合计 − 回款合计」（回款多于开票时为预收，单独列出）。
- 指定核销的回款先按指定关系冲掉，剩下的再先进先出。
- 结果按「客户 × 账龄段」做透视表，总计应等于科目余额表里应收账款的期末余额（口径一致时）。

## 四、与客户对账

把我方明细和客户对账单放在两张表，按以下顺序匹配，每一步匹配上的打标记，剩下的进入下一步：

1. 单号（发票号 / 订单号）完全一致；
2. 金额一致且日期相差不超过 N 天（N 放参数格）；
3. 一对多 / 多对一：客户一笔付款对应我方多张发票（合并付款），金额之和相等。

- 匹配不上的两边各自列出来，写明差异金额；**有多种可能匹配的不要自动选**，标「待确认」交给用户。
- 两边合计差额 = 未匹配项目差额之和，这一条对不上说明匹配过程有重复或遗漏。

## 五、银行余额调节表

```
企业银行存款日记账余额 + 银收企未收 − 银付企未付
= 银行对账单余额 + 企收银未收 − 企付银未付
```

两边调节后余额必须相等；不等时差额就是还没找到的未达账项或记账错误。调节表不是做账，不要改日记账。

## 六、坏账准备

按账龄计提时，各段的计提比例是公司会计政策，放参数表由用户提供；不要自己设定比例。
单项计提（已知有问题的客户）优先于组合计提，别重复计提。

## 常见报错

| 现象 | 常见原因 | 怎么办 |
|---|---|---|
| 账龄全部落在 0-30 天 | 截止日或起算日是文本 | 转成真正的日期 |
| 未核销余额合计 ≠ 开票 − 回款 | 发票没按客户、日期排序；同日多张发票累计重复 | 先排序；同日用行号累计 |
| 账龄透视总计 ≠ 应收余额 | 口径不同（含税 / 不含税、是否含预收、是否已减坏账） | 列出差异原因，不要硬调 |
| 对账差额在两边来回跳 | 同一笔被匹配了两次 | 匹配上的打标记，后续步骤排除 |
