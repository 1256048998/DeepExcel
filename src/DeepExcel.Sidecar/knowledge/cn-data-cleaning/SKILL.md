# 中文数据清洗

中文业务表的脏数据有固定的几类。先摸清每类有多少，告诉用户，再动手；能保留原列就保留原列。

## 流程

1. 摸底：inspect_sheet 看列类型，find 搜典型脏值（全角空格「　」、「万」、「NULL」、「/」）。
2. 汇报：每一类问题各有多少格、举一两个例子；有歧义的（0 算不算空？「—」是 0 还是没填？）先问。
3. 清洗：优先写到新列（原列名 +「_清洗」），或用户同意后原地改（修改前会自动备份）。
4. 核对：清洗前后行数、非空格数、合计值对比；抽查首行、末行、中间几行。

## 一、全角 / 半角

- 常见：全角数字「１２３」、全角字母、全角空格「　」(U+3000)、全角标点「，（）：」混进数字和代码列。
- 公式：`=ASC(A2)` 把全角字符转成半角（中文版 Excel 和 WPS 都支持）。
- VBA：`StrConv(s, vbNarrow, 2052)`——要带 2052（中文区域），否则在非中文系统上可能不转。
- 注意：姓名、地址这类中文文本里的全角标点通常是对的，不要一刀切转半角；只转数字、编码、金额列。

## 二、日期

| 原始写法 | 做法 |
|---|---|
| 2026年9月25日 | `=DATE(LEFT(A2,FIND("年",A2)-1), MID(A2,FIND("年",A2)+1,FIND("月",A2)-FIND("年",A2)-1), MID(A2,FIND("月",A2)+1,FIND("日",A2)-FIND("月",A2)-1))` |
| 2026.9.25 / 2026-9-25 / 2026/9/25 | 把 . 换成 /，再按年月日拆：`=DATE(LEFT(A2,4), MID(...), ...)`；别直接依赖 DATEVALUE，它随系统区域设置变 |
| 20260925（八位数字） | `=DATE(INT(A2/10000), MOD(INT(A2/100),100), MOD(A2,100))` |
| 46290 这类五位数 | 本来就是日期，只是格式成了常规：改数字格式为 `yyyy-mm-dd` 即可，不要改值 |
| 9月25日（没有年份） | 问用户是哪一年，不要自己猜 |
| 二〇二六年九月 | 中文数字，先逐字映射成阿拉伯数字 |

- 转完用 `=ISNUMBER(B2)` 检查：日期在 Excel 里是数字，文本日期不能参与排序和计算。
- 两位年份（26-9-25）、日月顺序可疑（2026.1.2 是 1 月 2 日还是 2 月 1 日）：问用户。

## 三、金额与单位

- 「1.2万」→ 12000，「3.5亿」→ 350000000：去掉单位字再乘 10^4 / 10^8。
- 「12,345.67元」「¥1,234」「￥1,234」（后者是全角人民币符号）：去掉千分位逗号和货币符号。
- 「(1,234)」在财务表里是负数。「-」「—」在报表里通常表示 0，在台账里可能表示没填：问。
- 表头写着「单位：万元」的表，数值已经是万元，换算时不要再除一次；换算后把单位写进表头。
- 只想「显示成万元」而不改数值：数字格式 `0!.0000"万"`（12345 显示为 1.2345万，合计仍按原值算）。
- clean_amount 工具处理千分位和货币符号；「万」「亿」、括号负数，用它之前先抽查结果。

## 四、身份证号、银行卡号被科学计数法吞掉（最要紧）

Excel 的数字只有 15 位有效数字。18 位身份证号、16–19 位银行卡号如果被当成数字存进去，
**第 16 位以后的数字已经变成 0，永久丢失**，改格式、加引号都找不回来。

- 识别：该列是数字类型、显示成 `4.10102E+17`，或变成文本后以「000」结尾。
- 处理：告诉用户这些号码已经损坏，需要从源文件重新导入——导入前先把该列设为「文本」格式，
  或在号码前加英文单引号。**绝对不要自己补全或编造后三位。**
- 以文本存的号码是好的（包括末位是 X 的身份证）。可以用校验位核对真伪：
  `=MID("10X98765432", MOD(SUMPRODUCT(--MID(A2,ROW($1:$17),1), {7;9;10;5;8;4;2;1;6;3;7;9;10;5;8;4;2}), 11)+1, 1)=UPPER(RIGHT(A2))`
- 同类问题：以 0 开头的工号、邮编、区号被存成数字后丢了前导 0——`=TEXT(A2,"000000")` 可以按固定位数补回来，
  但要先确认原来是几位。

## 五、空值的各种写法

空字符串、空格、全角空格、「NULL」「null」「N/A」「#N/A」「无」「空」「-」「—」「/」「待定」……

- 先统计各种写法各有多少，给用户看，问哪些算空。
- **0 不是空**：数量为 0、金额为 0 通常是有意义的值。
- 统一成真正的空单元格，还是统一成某个标记（如「未填」），听用户的。

## 六、看不见的字符

- 不间断空格 CHAR(160)：网页复制来的数据常见，`TRIM` 去不掉，要 `SUBSTITUTE(A2,CHAR(160),"")`。
- 换行 CHAR(10)、制表符：`CLEAN` 能去掉 0–31 号控制字符。
- 零宽字符（U+200B）：肉眼看不见，但会让 VLOOKUP 匹配失败。匹配不上又看不出差别时怀疑它，
  用 `=LEN(A2)` 和看起来的字数对比。
- 首尾空格：`TRIM` 会去掉首尾空格，并把中间的连续空格压成一个——中间空格有意义时（固定格式编码）别用。

## 七、文本型数字

- 表现：单元格左上角绿色三角、左对齐、SUM 结果偏小（SUM 忽略文本）。
- 转换：`=--A2` 或 `=VALUE(A2)`；带千分位的先去逗号。
- 查找用的编码列（工号、订单号）两边类型必须一致：一边是文本「001」、一边是数字 1，VLOOKUP / XLOOKUP 会返回 #N/A。

## 常见报错

| 现象 | 常见原因 | 怎么办 |
|---|---|---|
| VLOOKUP 返回 #N/A，但值看起来一样 | 一边文本一边数字；首尾空格；CHAR(160)；零宽字符 | LEN 对比，TRIM + SUBSTITUTE 清一遍，统一类型 |
| 日期转换后变成 #VALUE! | 字符串里有空格、全角数字，或格式不在预期里 | 先 ASC + TRIM，再拆年月日 |
| 身份证号末三位是 000 | 被当数字存过，已损坏 | 从源文件以文本重新导入，不要补 |
| 清洗后合计变了 | 删了不该删的行、把 0 当成空 | 对比清洗前后行数和合计，找出差异行 |
