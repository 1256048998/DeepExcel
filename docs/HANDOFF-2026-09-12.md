## 三、三条不能违反的约束

违反任何一条都会破坏已有设计，改之前先读对应的测试。

**1. 出口路由：客户端绝不自己判断 BYOK / 托管**

`GET /api/v1/session/endpoint` 返回什么，客户端就用什么。客户端里出现 `if plan == ...` 就破坏了整个设计——而且客户端未签名、可被任意修改，客户端侧判断本来就不是强制手段。M6 翻开关必须零客户端改动。

锁定测试：`server/tests/test_endpoint_routing.py::test_flipping_to_hosted_requires_no_client_change`、`src/DeepExcel.Tests/SidecarRoutingTests.cs`

**2. 隐私过滤必须在服务端执行**

遥测白名单（`server/app/routers/telemetry.py`）和技能脱敏（`server/app/routers/skills.py`）在客户端也做一遍，但**服务端那遍才是保证**。客户端那遍的作用是让数据根本不离开机器。

**3. 「允许并记住」只适用于能力型授权**

批准过一次 `delete_rows` 不等于批准之后任何一次删除——下一次可能删 200 行。只有 VBA / Python / send_keys 这类"我信任它能跑代码"的授权适合记住，见 `sidecar.py` 的 `_REMEMBERABLE_TOOLS`。

## 四、剩下没做的

**支付渠道接入** —— 微信支付 / 支付宝需要企业商户号，申请周期按月计。订单、权益激活、续费延长、回调幂等全部已实现并有测试，**缺的只是最后那个"谁把订单标记为已支付"**。目前由运营在后台手工标记，每次写审计日志。商户号下来后接上回调即可，下游一行不用改。

**上游供应商密钥** —— 代理本身完成，但 `UPSTREAM_*` 环境变量需要填真实供应商密钥。未配置时 `/v1/messages` 返回 502 `no_upstream`，不会静默失败。

**Windows Sandbox 全新机器验收** —— 见下一节，这是唯一还没闭合的验证缺口。

**WPS 端登录** —— **按路线图刻意不做**。除非遥测显示 WPS 占比 > 20%，WPS 维持"保证不崩、不追新功能"。这是决定，不是遗漏。

**面板输出格式** —— 用户反馈 AI 回复空行过多、信息密度低。属于 `system_prompt.py` 的输出风格问题，未处理。

## 五、唯一未闭合的验证缺口

**Windows Sandbox 安装验收从未执行。**

Windows 11 Pro 支持，但 `Containers-DisposableClientVM` 功能未启用。启用需要管理员权限**并重启机器**：

```powershell
Enable-WindowsOptionalFeature -FeatureName "Containers-DisposableClientVM" -Online
```

重启后：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-install-sandbox.ps1 -Launch
```

它会在干净沙箱里跑：SHA-256 校验 → 静默安装 → 双视图 COM 注册与激活 → 卸载残留检查。

**为什么这条重要：** 开发机永远装得上——它已经有注册表项、有运行时、没有下载来源标记。v0.4.11 → v0.4.17 连续七个版本栽在这里，就是因为没在干净机器上验证过。

## 六、这一轮踩到的坑（下次别重复）

按"只有真实环境才会暴露"排序。每一条都已修复并加了守卫。

**1. `Range.Value2` 返回 OLE 日期序列号**

不转换的话每个日期列都被报成 4 万多的数字。**看起来完全合理，所以没有任何东西会报警**，模型会直接照做。现按单元格数字格式还原（`SheetProfiler.ConvertOleDates`）。

**2. 测试"全部通过"是假的**

C# 全量跑 66 项全过，但单独跑 `SessionManagerTests` 有 10 项失败——System.Text.Json 引用 Unsafe 4.0.4.1 而实际文件是 6.0.0.0，**通过与否取决于程序集加载顺序**。已用 `-appdomains denied` 固定。绿色但无意义的测试比红色危险。

**3. `requirements.txt` 里 `alembic==1.16.6` 根本不存在**

凭记忆写的版本号，九个依赖里五个是错的。只有第一次 docker build 才暴露。现在版本号从可用环境导出，不手写。

**4. `httpx` 被错列为 dev 依赖**

它是代理模块的运行时依赖，本地由 pytest 带入所以看不出来。生产镜像里 import 就炸，**整个服务起不来**。守卫：`server/tests/test_requirements.py` 检查 `app/` 里 import 的每个第三方包都在 `requirements.txt` 中。

**5. `audit_logs.id` 上多余的唯一约束**

主键本来就唯一。SQLite 毫无反应，Postgres 立刻报模型与迁移不一致。已加删除迁移。这是"必须对真实数据库跑测试"的直接理由。

**6. 安装器结尾的 `Floating point underflow`**

完成提示的 `MsgBox` 写在 `DeinitializeSetup` 里，而那个钩子在**向导窗口销毁之后**执行。安装本身完全成功（日志里 `Installation process succeeded.`），但最后弹一个崩溃样的错误框——对一个已经要用户点"仍要运行"的未签名安装包，这等于宣告失败。已移到 `CurStepChanged(ssDone)` 并实测验证。

诊断过程中先后猜过 `MoveFileEx` 声明不匹配、MSXML 改写 FPU 控制字、`IsUninstaller()` 非法调用，**全部用最小 `.iss` 探针实测证伪**。真正指向答案的是 Inno 安装日志里 `Deinitializing Setup` 出现在异常**之后**这一行。

## 七、两个已知但未修的小问题

**`/VERYSILENT` 下 `WizardSilent` 返回 False** —— 静默安装仍会弹完成框。`/SUPPRESSMSGBOXES` 能压住，IT 批量部署不受影响，但这个判断本身不可靠。修它需要另一轮实测。

**`MinimumStepsForSkill = 3`** —— 少于 3 步的任务不提议保存为技能。这个阈值是拍的，没有数据支撑。等遥测跑起来后应该用真实数据校准。

## 八、给下一个会话的建议起点

按价值排序：

1. **启用 Windows Sandbox 跑安装验收**（需要用户重启机器）。M1 的全部价值押在安装链路上。
2. **提交这 58 个文件**。当前全部改动未 commit。
3. **修面板输出格式** —— 用户明确反馈过空行太多、信息密度低。
4. **实现自动更新器**（路线图 M1.1b 第 1 条，标为"总摩擦降幅最大"但尚未实现）。要点：客户端内嵌 Ed25519 公钥，服务端发布签名的 `update.json`，更新器验签 + 校验 SHA-256 后才执行。由已安装程序下载的更新包不带 MOTW，不触发 SmartScreen——首装痛一次，之后所有更新静默完成。

**不要**在没有遥测数据的情况下去调 M3 的采样参数或 M5 的技能阈值。北极星指标（任务一次成功率）现在可测量了，让它说话。
