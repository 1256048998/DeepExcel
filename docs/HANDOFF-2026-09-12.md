## 三、五条不能违反的约束

违反任何一条都会破坏已有设计，改之前先读对应的测试。

**1. 出口路由：客户端绝不自己判断 BYOK / 托管**

`GET /api/v1/session/endpoint` 返回什么，客户端就用什么。客户端里出现 `if plan == ...` 就破坏了整个设计——而且客户端未签名、可被任意修改，客户端侧判断本来就不是强制手段。M6 翻开关必须零客户端改动。

锁定测试：`server/tests/test_endpoint_routing.py::test_flipping_to_hosted_requires_no_client_change`、`src/DeepExcel.Tests/SidecarRoutingTests.cs`

**2. 隐私过滤必须在服务端执行**

遥测白名单（`server/app/routers/telemetry.py`）和技能脱敏（`server/app/routers/skills.py`）在客户端也做一遍，但**服务端那遍才是保证**。客户端那遍的作用是让数据根本不离开机器。

**3. 「允许并记住」只适用于能力型授权**

批准过一次 `delete_rows` 不等于批准之后任何一次删除——下一次可能删 200 行。只有 VBA / Python / send_keys 这类"我信任它能跑代码"的授权适合记住，见 `sidecar.py` 的 `_REMEMBERABLE_TOOLS`。

**4. 更新签名私钥绝不能出现在服务端或仓库里**

服务端只原样转发已签名的清单。这不是实现细节，而是整个更新安全模型的全部内容：**服务端被拿下也推不了更新**。一旦私钥上了服务端，这条性质就没了，而且没有任何测试会因此变红。

同理，客户端 `EmbeddedUpdateKey` 里的公钥常量只能由 `scripts/update_signing.py genkey` 改写，不要手改——手改会让公钥和私钥悄悄不一致，所有客户端静默停止升级，看起来和"还没人升级"一模一样。打包脚本会在构建时回验以拦住这种情况。

锁定测试：`scripts/test_package_release.py::test_update_manifest_guards`、`scripts/test_updater_e2e.py`

**5. 更新遥测只能带版本号和分类码**

`update_event` 绝不能加入更新源地址、暂存路径或异常原文。这三样是把用户数据夹带进遥测的常见途径，而这个模块的**每一条错误消息都至少含其中之一**——所以 `UpdateTransportException` 的分类码在抛出那一行就定好，不是事后从消息里解析。加字段就是做一次隐私决定。

锁定测试：`UpdateServiceTests.Telemetry_never_carries_a_url_a_path_or_exception_text`（白名单式断言：码必须是标识符，版本必须能解析）、`test_telemetry.py::test_update_event_drops_the_feed_url_and_the_staging_path`

## 四、剩下没做的

**支付渠道接入** —— 微信支付 / 支付宝需要企业商户号，申请周期按月计。订单、权益激活、续费延长、回调幂等全部已实现并有测试，**缺的只是最后那个"谁把订单标记为已支付"**。目前由运营在后台手工标记，每次写审计日志。商户号下来后接上回调即可，下游一行不用改。

**上游供应商密钥** —— 代理本身完成，但 `UPSTREAM_*` 环境变量需要填真实供应商密钥。未配置时 `/v1/messages` 返回 502 `no_upstream`，不会静默失败。

**干净机器上的 COM 激活定性** —— 见下一节。Sandbox 验收本身已跑过并抓到过一个发布阻断缺陷；剩下的 `0x80070002` 需要一台装了 Excel 的干净机器才能判断，Sandbox 没有 Office，覆盖不了。

**WPS「装了用不了」已定性并修复，但还没发版给用户验证** —— 用户 2026-09-13 报告：真实电脑上 Excel 端正常、WPS 端装了用不了，且 WPS 占比"蛮多"。

真因是 **`jsplugins.xml` 没打进发布包**。它是加载项清单，声明入口 url 和按钮的 onAction 回调。开发路径的 `build-wps.ps1` 一直复制它，发布路径的 `WPS_ITEMS` 漏了——于是用户装到的加载项只有 `ribbon.xml` 能渲染出选项卡，**所有 JS 回调都是死的**：选项卡在、图标不显示、点"打开面板"毫无反应。干净沙箱 + 真实 WPS 已复现，修复见 `85ea244`。

**`enable="enable_dev"` 这条嫌疑已排除**，别再查它。两重独立证据：① 金山官方 wpsjs 工具链源码（`.local-signing/wpsjs-inspect/`）里 `build.js` 的 `CreatePublishXml`——生成面向终端用户的分发包那条路径——写的就是 `enable_dev`；② 沙箱实测里选项卡**出现了**，若 enable_dev 导致不加载则连选项卡都不会有。这恰好回答了 `verify-install-sandbox.ps1` 里那道人工判断题，不必再去沙箱装 WPS 看 GUI。

守卫已加（`test_package_release.py::test_every_wps_source_file_is_packaged`）：以 `git ls-files src/DeepExcel.Wps` 为唯一真相，任何被跟踪的 WPS 源文件没进 `WPS_ITEMS` 就变红——只补一个文件名挡不住下一个。

**剩下的动作：发一版，请报故障的用户确认 WPS 端可用。**

**WPS 端登录** —— **按路线图刻意不做**。除非遥测显示 WPS 占比 > 20%，WPS 维持"保证不崩、不追新功能"。这是决定，不是遗漏。

**更新签名密钥** —— 自动更新链路已完整实现并测通，但**尚未生成正式密钥**。内置公钥故意留空（=自动更新默认停用，不会联系任何地址）。开启需要用户决定私钥的离线保管位置：

```bash
python scripts/update_signing.py genkey --out <离线路径>
```

做完这一步后必须重新编译并发布一次客户端，之后的版本才能自动更新。详见 README 的「自动更新」一节。

## 五、唯一未闭合的验证缺口

**先更正一段过时描述：** 本文早期版本写"Sandbox 验收从未执行"。那已经不成立了——
`Containers-DisposableClientVM` 已启用（`C:\Windows\System32\WindowsSandbox.exe` 存在），
Inno Setup 也已装在 `%LOCALAPPDATA%\Programs\Inno Setup 6\`（**不在** Program Files，
`where ISCC` 查不到，别据此判定未安装），`dist/DeepExcel.Setup.exe` 已真实编译产出。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify-install-sandbox.ps1 -Launch -NoPause
```

**`-NoPause` 是 2026-09-18 加的**，用它跑就不需要有人守着。此前脚本在写完结果后会停在
「Press Enter to close」——对守在屏幕前的人是对的，对其他所有情况是错的：无人值守的运行
永远不返回，沙箱窗口一直挂在桌面上。守卫里特意锁了最微妙的一条：`-NoPause` 必须通过
**LogonCommand** 传进 guest。宿主侧的 `.wsb` 用 LogonCommand 重新调用同一个脚本，开关加在
宿主侧而 LogonCommand 里漏传的话，参数会被正常接受、正常报告为已设置，然后什么都不做。

**验收跑过，而且抓到过一个真实的发布阻断缺陷：** 文件装好后 `ssPostInstall` 里
`DeepExcel.Repair.exe --repair --quiet` 退出 1 → `RunAndRequire` 抛异常 → 回滚注册 →
**但安装器仍返回 0**。用最小 `.iss` 探针独立证实：Inno 把 `CurStepChanged` 里抛的异常
当非致命。已修（置 `PostInstallFailed`，在 ssDone 里 `ExitProcess(4)`），守卫在
`scripts/test_installer_script.py`，见 commit `eb960d6`。

### 真正还没定性的：COM 激活 `0x80070002`

已排除：注册表项错误（mscoree / Assembly 0.5.0.0 / CodeBase 文件存在，64+32 两视图都对）、
载荷缺失（16 个程序集齐全，含 interop 15.0.0.0，与引用版本一致）、.NET 缺失
（4.8.1 Release 533320）。

**Windows Sandbox 查不下去了，因为它没有 Office。** 验收脚本头部自己就写了这一点：
它覆盖不了任何依赖 Excel 的步骤，所以沙箱里无法判断 `0x80070002` 是真缺陷还是
"这台机器压根没有 Excel"的假象。开发机同样不行——它本来就不构成干净验证。

**要闭合它，需要一台装了 Excel 的干净 Windows 机器**（没装过 DeepExcel 的同事机器，
或一个装了 Office 的 VM）。这是目前唯一卡在环境上、而非代码上的验证。

### WPS 那道人工判断题已重新对准（2026-09-18）

脚本原来问的是"Ribbon 里有没有 DeepExcel 选项卡？有就说明 enable_dev 没问题"。那个问题
**已经有答案了**，继续问只会让人重答一遍旧问题，而真正的 bug 在更里面一层。现在改成问两件

**为什么这条重要：** 开发机永远装得上——它已经有注册表项、有运行时、没有下载来源标记。
v0.4.11 → v0.4.17 连续七个版本栽在这里，就是因为没在干净机器上验证过。

## 六、这一轮踩到的坑（下次别重复）

按"只有真实环境才会暴露"排序。每一条都已修复并加了守卫。

**1. `Range.Value2` 返回 OLE 日期序列号**

不转换的话每个日期列都被报成 4 万多的数字。**看起来完全合理，所以没有任何东西会报警**，模型会直接照做。现按单元格数字格式还原（`SheetProfiler.ConvertOleDates`）。

**2. 测试"全部通过"是假的**

C# 全量跑 66 项全过，但单独跑 `SessionManagerTests` 有 10 项失败——System.Text.Json 引用 Unsafe 4.0.4.1 而实际文件是 6.0.0.0，**通过与否取决于程序集加载顺序**。已用 `-appdomains denied` 固定。绿色但无意义的测试比红色危险。

**3. `requirements.txt` 里 `alembic==1.16.6` 根本不存在**

凭记忆写的版本号，九个依赖里五个是错的。只有第一次 docker build 才暴露。现在版本号从可用环境导出，不手写。

**4. `httpx` 被错列为 dev 依赖**

它是代理模块的运行时依赖，本地由 pytest 带入所以看不出来。生产镜像里 import 就炸，**整个服务起不来**。守卫：`server/tests/test_requirements.py` 检查 `app/` 里 import 的每个第三方包都在 `requirements.txt` 中。

**5. `audit_logs.id` 上多余的唯一约束**

主键本来就唯一。SQLite 毫无反应，Postgres 立刻报模型与迁移不一致。已加删除迁移。这是"必须对真实数据库跑测试"的直接理由。

**6. 安装器结尾的 `Floating point underflow`**

完成提示的 `MsgBox` 写在 `DeinitializeSetup` 里，而那个钩子在**向导窗口销毁之后**执行。安装本身完全成功（日志里 `Installation process succeeded.`），但最后弹一个崩溃样的错误框——对一个已经要用户点"仍要运行"的未签名安装包，这等于宣告失败。已移到 `CurStepChanged(ssDone)` 并实测验证。

诊断过程中先后猜过 `MoveFileEx` 声明不匹配、MSXML 改写 FPU 控制字、`IsUninstaller()` 非法调用，**全部用最小 `.iss` 探针实测证伪**。真正指向答案的是 Inno 安装日志里 `Deinitializing Setup` 出现在异常**之后**这一行。

## 八、给下一个会话的建议起点

按价值排序：

1. **在一台装了 Excel 的干净机器上定性 COM 激活 `0x80070002`**。Sandbox 已启用且跑过，但它没有 Office，查不下去了。M1 的全部价值押在安装链路上。
2. **生成更新签名密钥并发一版**。自动更新的代码路径全部测通了，但真实发布中一次都没跑过，因为还没有正式密钥。这是把它从"已实现"变成"在用"的唯一一步。
3. **M1.1b 第 2 条：杀软误报自查与白名单申诉**。规划里写明"国内场景比 SmartScreen 更致命"，至今未做。打包后送多引擎扫描、记录每次发版的检出情况、向 360 / 火绒 / 腾讯 / Microsoft WDSI 提交申诉。**不要为此把安装包上传到 VirusTotal 这类服务**——上传等于公开发布该文件，付费用户可下载。按 SHA-256 查询不涉及这个问题。
4. **M1.1b 第 4 条：下载落地页图文指引**。规划称"性价比最高的转化优化"，至今未做。需要真实截图，做不了纯代码版本。

**不要**在没有遥测数据的情况下去调 M3 的采样参数或 M5 的技能阈值。北极星指标（任务一次成功率）现在可测量了，让它说话。
