### 11-23：WPS 换路线、预览补齐、自动更新加固

- **WPS 改走 Excel 的同一个 COM 加载项**（`2a2ab59`）。真机（WPS 12.1.0.29690 个人版）实测：
  WPS 的 JS 加载项宿主没有 Node，原 JS 加载项整套跑不起来；而 WPS 直接加载 COM 加载项时
  功能区、WebView2 面板、sidecar、模型、读写工具都通。安装器把 COM 加载项登记到
  `HKCU\Software\Kingsoft\Office\ET\AddIns` 并写白名单、清禁用名单，从 `publish.xml` 撤掉 JS 加载项。
  同时修了 WPS 上 4 处兼容问题（带表名的 Range 地址、面板宽度、输入框高度、功能区图标）。
  - 「技能库」菜单入口已隐藏（产品决定，`SkillPanel` 和后端保留，见 `App.tsx`）。
  - 一键在 Windows Sandbox 里试用 WPS 版：`scripts/try-wps-sandbox.ps1`（开发机上沙箱启动约
    4 分钟必崩，原因未定位，见 `README-WPS.md`）。
  - 随后整套 WPS JS 加载项（`src/DeepExcel.Wps/`、`build-wps.ps1`、`register-wps.ps1`、Node 测试）
    从仓库和安装包删除；安装和卸载都会清理旧版本留下的 `publish.xml` 节点和 `jsaddons\DeepExcel_*`
    目录。`DEPLOYMENT.md`、`README-WPS.md` 已改写为 COM 路线。
- **执行前预览补齐**（`6216d83` … `e18d831`）：`PreviewPolicy` 里列的 19 个写入工具都有了精确
  预览（原来只有 7 个，其余落到「精确预览尚未实现，已自动创建快照」），另修 `write_range`、
  `delete_columns` 两处已有预览的 bug。清洗规则抽成预览与执行共用的 `Tools/CleaningRules.cs`。
  `rollback` 仍无预览。
- **自动更新加固**（`14d86cd` … `a1d8eb7`）：
  - 文件租约替代进程名判断：加载了 DeepExcel 的进程持有 `%LOCALAPPDATA%\DeepExcel\updates\leases\<pid>.lease`，
    WPS 文字、关掉了加载项的 Excel 不再挡更新；
  - 安装失败自动回滚：新版本确认能启动后把自己的已签名清单和安装包留在 `updates\rollback\<版本>\`，

    且没人持有租约就回滚；重开的是 WPS 时暂不等回执；
  - Excel 关闭时静默安装已就绪的更新；
  - 遥测新增 `apply / rolled_back`，后台看板计入「更新失败」。**服务端要重新部署才会收下这个值。**

## 三、仍然有效的事实（逐条对过代码）

- **更新签名公钥仍为空**（`Updates/UpdateSigning.cs` 的 `ModulusBase64 = ""`）。也就是说：发出去的
  版本自动更新整体是关着的，知识包下发也是（它用同一把公钥验签，`KnowledgeSync` 在公钥为空时
  直接跳过）。上面那一大段自动更新加固要等生成正式密钥、发一版之后才在用户机器上生效。
  生成只能用 `python scripts/update_signing.py genkey --out <离线路径>`，私钥离线保管、绝不上服务端。
  09-12 定的是「签名暂缓」，这一步要用户本人决定私钥放哪。
- **支付仍是运营手工标记已支付**（`server/app/routers/billing.py` 的 `mark_paid`，每次写审计日志）；
  微信 / 支付宝回调没接，等商户号。
- **代码签名证书没买**，发布形态是未签名安装包 + `SHA256SUMS.txt`。
- **出口路由约束不变**：客户端只应用服务端下发的 EndpointConfig，绝不自己判断 BYOK / 托管。
- Excel 与 WPS 现在跑的是同一个 COM 加载项，共用同一份 `config.json` 和 DPAPI 凭据。

## 四、没闭合的验证缺口

1. **COM 激活 `0x80070002`** 仍未定性，仍需一台装了 Excel、没装过 DeepExcel 的干净机器
   （09-12 那份第五节）。注意 `DEPLOYMENT.md` 里另有一个沙箱「映射 `%LOCALAPPDATA%` 目录报
   `0x80070002`」的坑，那是 Claude 桌面（MSIX）重定向 `AppData\Local` 造成的，和 COM 激活不是一回事。
2. **WPS 走 COM 的完整链路**只在一台真机（个人版 12.1）上跑通过；安装器登记 WPS 的那部分没在
   干净机器上从零装过；企业版 / 其他版本未测。
3. **执行前预览新增的读取**（整块 `Range.Value`、`UsedColumnCount`、`SheetExists`）没在真 Excel 上跑；
   清洗、排序的确认面板需要真机看一次。
4. **自动更新的回滚与启动回执**只用桩安装程序、桩宿主验证过；真签名 + 真 Inno 安装包 + 真 Excel
   的一次完整「重启安装 → 回执 / 回滚」没跑过（也跑不了，见上面签名公钥）。WPS 是否在用户启动的
   实例上触发 `OnStartupComplete`（启动回执写在那之后）没验证，所以 WPS 暂不等回执。
5. 服务端真实 Postgres 那一遍这次没跑。

## 五、已知但没修的

- 自动更新：重开的 Excel 几秒内被关掉、或以安全模式启动，会被当成新版本没启动成功而回滚（代价：
  多一次重新提示）；租约上线前启动、至今未重启的旧 Excel 不持有租约，更新程序看不到它（只在过渡期）。
  第一次手动安装后的第一次自动更新没有回滚包（要覆盖需让发版流水线把已签名清单打进安装包、
  安装器顺手放进 `rollback\`，要改 `.iss`）。
- 执行前预览：读取器不带合并单元格信息，`sort_data` 遇到合并单元格时执行器会拒绝，而预览仍显示
  排序结果（只会多报不会少报）。
- `MinimumStepsForSkill = 3` 仍是拍的（技能库入口现已隐藏，优先级更低了）。
- 共享仓库里本地引用 `refs/heads/feature/claude-sdk-migration` 指向缺失对象，`git fetch` 会整体失败；
  用 `git ls-remote origin` 核对远端，或删掉 / 修复这个本地引用（删之前确认没人要它）。
