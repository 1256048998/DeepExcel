# DeepExcel 改进路线（2026-09-25）

来源：对同类 Excel AI 插件做了一次全方位对照研究，并逐项核对了我们自己的代码。本文只记录**对 DeepExcel 的结论和要做的事**；对照研究的原始材料只留在本地，不入库。

【确认】= 已对照代码核实；【推断】= 需要真机复现。

---

## 参照系：Claude Code 在代码库里怎么干活，DeepExcel 就在工作簿里怎么干活

DeepExcel 本质上是「工作簿里的 Claude Code」。Claude Code 在代码库里已经被验证过的那套机制，每一条都有直接对应的工作簿版本。与其从零设计，不如逐条对照：

| Claude Code 的机制 | 它解决的问题 | DeepExcel 的对应物 | 现状 |
|---|---|---|---|
| **每次编辑自动存检查点，`/rewind` 回到任意一步**（代码和对话一起退） | 用户敢放手让 agent 改 | 每次写入前自动快照；消息流里每个写入步骤下挂「回到这一步之前」 | 写入不自动备份；回退藏在历史弹窗；回滚本身会丢数据（F1） |
| **先读后写**：没 Read 过的文件，Edit 直接拒绝 | 不会覆盖自己没看过的内容 | 写入目标区域若本会话从未读过、且非空，写工具拒绝并要求先读 | 没有 |
| **读后被改检测**：文件在 Read 之后被外部修改，Edit 报错要求重读 | 不和用户的并发修改打架 | 记录每次读取的区域指纹；写入前比对，用户在此期间改过就拒绝并要求重读 | 没有 |
| **Edit 显示 diff** | 每一处改动一眼可见 | 写入结果在消息流里内联显示「原值 → 新值」的小表（大改动折叠成摘要 + 可展开） | 只有执行前预览（M4），执行后看不到改了什么 |
| **一个工具调用 = 一行 `⏺ 工具(参数) ⎿ 结果摘要`** | 过程可读、失败可见 | 每步一行人话 +状态点，完成时补一行结果摘要 | 只显示「已调用 N 个工具」和原始工具名 |
| **TodoWrite 计划，实时勾选** | 多步任务有进度感 | 输入框上方的计划胶囊（当前步骤 + 2/5） | 有 create_plan / update_plan，但界面不展示 |
| **Esc 中断；运行中可以继续输入，消息排队在下一步读到** | 中途纠偏，不用停下重来 | 停止 = interrupt + 排空 + 可 resume；运行中输入框不锁，补充指令在下一次工具调用前注入 | 停止只取消读循环（F9）；运行中锁输入框 |
| **Plan mode：先出方案、用户批准再执行** | 大改动前对齐意图 | 「只出方案」模式：agent 只读不写，产出一份变更计划（涉及哪些表、哪些区域、怎么做），用户批准后执行 | M4 是逐操作确认，没有方案级确认 |
| **权限模式**：默认询问 / 自动接受编辑 / plan | 同一个产品适配谨慎和放手两类用户 | 「每步确认 / 本次会话自动应用写入（仍可逐步回退）/ 只出方案」 | 只有逐操作确认 + 能力型「允许并记住」 |
| **Grep / Glob：按需搜索，而不是把整个仓库塞进上下文** | 大仓库也能精准定位 | `find`（跨表搜值和公式）、`list`（表、命名区域、ListObject、透视表）、分页 `read_range(offset, limit)`；结构摘要只给骨架，细节让 agent 自己查 | 结构摘要 + 读取截断 200 行，没有搜索 |
| **跑测试 / lint 验证自己的改动** | 不靠「我觉得改好了」 | 每次写入后自动体检：公式错误数前后对比、新增外部链接、引用不存在的表、抽样回读；结果直接附在工具返回里 | 没有；模型自己不回读就宣布完成 |
| **CLAUDE.md：项目记忆** | 跨会话不重复踩坑 | 每个工作簿一份记忆：结构怪癖、用户偏好（金额单位、格式习惯）、禁区（「汇总表别动」）、做过的改动 | 没有 |
| **Skills：按需加载的专业知识** | 知识不常驻上下文 | `load_skill`：财务勾稽、工资个税、中文数据清洗……按需加载 | M5 是录制回放，没有知识层 |
| **子 agent：隔离上下文并行探索** | 大任务不撑爆主上下文 | 大工作簿按表派子 agent 并行摸底，只把结论交回主 agent（claude-agent-sdk 原生支持 `agents`） | 没有 |
| **自动压缩，且告诉用户** | 长任务不断片 | 压缩开始/完成都显示状态行 | 压缩事件在两个宿主都被丢弃（F10） |
| **Hooks：用户可编程的护栏** | 团队规则强制执行 | 工作簿记忆里的禁区由 PreToolUse 强制执行，而不是只写在提示词里 | 没有 |
| **状态栏：模型、上下文占用、花费** | 用户对成本心里有数 | 终态行「完成 · 4 步 · 38 秒 · 消耗 N 点」（数字来自服务端） | 没有 |

执行前变更预览（M4）、隐私白名单、更新签名、列级语义统计是我们已有的优势，全部保留，在其上补齐这张表。

## 推进方式

- **按依赖顺序推进，不按人力排期。** 能并行的并行（不同子系统同时开多个会话或子 agent），每一步都以自动化验证收尾：C# / Python / 前端测试全绿，外加截图回归。
- **地基先行。** 「事件信封」「写前自动快照」「目标工作簿可指定」这三块是后面几乎所有能力的前提，先做。
- **让模型做模型擅长的，让代码做确定性的事。** 搜索、判断、规划交给 agent；备份、校验、计数、冲突检测这类必须 100% 可靠的放在代码里强制执行，不靠提示词约束。

### 事件信封

sidecar 输出统一的 `{"type":"ui_event","event":{...}}`，C# 与 WPS 宿主不解析内容、按 WorkbookKey 原样转给 UI。现有 `stream_delta / stream_end / tool_use / compacted` 迁入。之后加任何展示事件，只改 sidecar 和 UI 两处。

```jsonc
{ "kind": "tool_start", "tool_use_id": "…", "name": "write_range", "params": { … } }
{ "kind": "tool_end",   "tool_use_id": "…", "is_error": false, "brief": "已写入 99 个单元格",
  "meta": { "cells": 99, "sheet": "销售" }, "diff": [ … ], "checkpoint_id": "…" }
{ "kind": "tool_gen",   "tool_use_id": "…", "phase": "start|delta|end", "field": "code", "text": "…" }
{ "kind": "status",     "status_kind": "api_wait|api_retry|compacting|compacted|model_fallback", "text": "…" }
{ "kind": "plan",       "items": [ { "text": "…", "state": "pending|running|done" } ] }
{ "kind": "error",      "error_kind": "upstream_api_error|timeout|cancelled|internal", "text": "…" }
{ "kind": "run_summary","num_turns": 4, "tool_steps": 6, "duration_ms": 38000 }
```

每个事件都带人话兜底 `text`；前端按 `*_kind` 本地化；error_kind 以服务端返回为准，客户端不自己判断 BYOK / 托管。

### 目标工作簿可指定

`IExcelActions` / `ToolDispatcher` 目前写死了 `_excelApp` 和 ActiveWorkbook。改成每次调用显式携带目标 Application / Workbook（会话绑定）。这一改同时修掉「用户切换工作簿后改错文件」这类问题，也是后面「副本试跑」的前提：所有现有工具都能直接 `target="lab"`。

## 第二层：像 Claude Code 一样干活（过程可见 + 可回退 + 自我验证）

1. **叙事行**：`ToolStep` 取代「已调用 N 个工具」。每步一行：状态点（运行中品牌色脉冲 / 完成绿 / 失败红）+ 一句人话，完成后补结果行；失败行默认展开错误摘要；连续多条已完成的只读步骤折叠成一行。参数与结果 JSON 只在开发者模式可见。
2. **中文文案目录**：`src/DeepExcel.UI/src/toolEvents/` 每个工具一份 start / done / fail 模板，变量来自参数和**结果**（done 文案只用结果里的数字）；vitest lint 扫描 `excel_tools.py` 的 `@tool` 名单，断言全覆盖、变量都能填上。放 UI 侧，Excel 与 WPS 共用。
3. **内联 diff**：`tool_end` 带上截断后的改动样本（地址、原值、新值），叙事行下可展开成小表；超过阈值只给「改了 N 格，涉及 X、Y 两张表」加抽样。
4. **每步检查点**：写入步骤的 `tool_end` 带 `checkpoint_id`，行下挂「回到这一步之前」，tooltip 写清「之后的修改也会一起回退，回退前的版本会另存一份」。依赖 F1、F5。
5. **先读后写 + 读后被改检测**：sidecar 记录本会话读过的区域及其指纹（Value2 / 公式哈希）。写入非空目标区域时，若从未读过则拒绝并要求先读；读过但用户在此期间改过，就拒绝并要求重读。这些判断在代码里强制执行，不靠提示词。
6. **写后自动体检**：写入和执行代码后，工具返回里自动附上公式错误数前后对比、新增外部链接、引用不存在的表、抽样回读的计算值。模型拿到的是「做完了，这是验证结果」，而不是「调用成功」。
7. **中断与排队**：Esc / 停止按钮 = interrupt + 排空（F9）；运行中输入框不锁，补充指令排队，在下一次工具调用前经 PreToolUse 注入，并提示模型「这不是错误，请先读新指令」。
8. **计划胶囊**：`create_plan / update_plan`（或 SDK TodoWrite）驱动输入框上方的进度胶囊；提示词规定「三步以上的任务先建计划」。
9. **状态行与终态行**：30 秒无进展显示「仍在等待模型服务」并原地计时，150 秒放弃并隔离；重试、压缩中、压缩完成、模型被服务端替换都是结构化状态行；回复末尾「完成 · 4 步 · 38 秒 · 消耗 N 点」。
10. **代码边写边显示**：`execute_vba / execute_jsa / execute_python` 的代码在生成过程中流式出现（默认折叠为「正在编写 VBA（已 42 行）」），节流后再发，避免挤爆 WebView2 消息队列。
11. **结构化错误**：错误不再拼进正文、不再写进历史；给出一句带下一步建议的话，并注明已完成的修改会保留。

### 界面

- **设计 token 层**：`src/DeepExcel.UI/src/theme/tokens.css`，把 `styles.css` 里的硬编码颜色和未定义变量全部改成语义 token。基准：品牌蓝 `#1A66D9`（白底对比 5.32:1）、冷灰中性色、信息性文字对比度 ≥ 4.5:1、字号 6 档（11 / 12 / 13 / 14 / 16 / 18）、4px 间距网格、圆角 4 / 6 / 8 / 12 / pill、阴影一律配真实 border；预留 dark 与 `forced-colors`。
- **消息排版**：助手消息去掉气泡、全宽正文；用户气泡改浅中性底；去掉「你 / 助手」标签。
- **滚动**：离底 60px 以上就停止自动跟随并出现「回到底部」；流式用 instant 滚动加 rAF 合帧；消息项 memo 化。
- **顶栏瘦身 + 输入坞**：顶栏只留新建、历史、账户、更多；模型选择和附件移到输入框工具条；容器查询保证 320px 不溢出。
- **截图回归**：`npm run ui:shots`，320 / 400 / 480 三个宽度 × 主要场景，作为每次界面改动的验收。

## 第三层：像 Claude Code 一样读懂上下文（按需搜索 + 结构理解）

原则：**摘要只给骨架，细节让 agent 自己查。** 取数靠宿主（C# / WPS JS 一次批量读出有界快照），算法放 `src/DeepExcel.Sidecar/perception/`，Excel 与 WPS 共用。WPS 由此首次获得与 Excel 相同的结构理解。

1. **搜索与列举工具**：`find(query, scope=values|formulas, sheets)`、`list(kind=sheets|names|tables|pivots|charts)`、`read_range(offset, limit)` 分页，读取截断时告诉模型下一页参数。这是 Grep / Glob / Read 的工作簿版。
2. **区块检测**：非空掩码做连通区域（合并单元格视为连通），丢弃被包含的孤岛；早停计数不计已访问格；只隔 1 个空行且列跨度高度重合的两块合并；块过多时保留主要块、其余只列范围。
3. **多级表头**：规则优先——逐行看填充率、文本/数字/日期占比、横向合并与覆盖关系，先认标题行再认最多 3 行表头，列标签自底向上拼路径（「扣款/养老/公司」）；拿不准时标「表头不确定」，交给 agent 去实读，而不是硬给结论。
4. **R1C1 公式模式**：按列求相同 R1C1 的游程并合并成矩形，模式 id 取 R1C1 文本哈希，用表头路径渲染成 `[数量]*[单价]`；同列多种模式标「公式不一致」；扫描截断时写「统计不完整」，不写数字。
5. **公式异常候选**：孤立偏离、疑似被改成死值、合计范围漏行、断链引用；排除合计行、表头、合并格、动态数组；只作候选、不自动修复。AI 写公式后对受影响区域自动跑一遍，并入「写后自动体检」。
6. **分层 `inspect_sheet`**：blocks / formulas / objects / dependencies 按需返回，每层独立标注 `complete | partial | error`。
7. **子 agent 摸底大工作簿**：表多或表大时，按表派子 agent 并行调用 inspect / find，只把结论交回主 agent，主上下文保持干净。
8. **覆盖诚实**：采样得出的写「样本结论」，COM 读不到时明确说明「沿用 N 分钟前的缓存」。
9. **企业透明加密**：附件读取前嗅探文件头（xlsx 应为 `PK\x03\x04`，xls 应为 `D0 CF 11 E0`），都不是就直接提示「文件可能被企业加密软件保护，请在 Excel 中打开后再处理」；快照一律走 SaveCopyAs。

## 第四层：像 Claude Code 一样有记忆、有知识、有模式

1. **工作簿记忆（CLAUDE.md 的工作簿版）**：本地 `workbooks/<hash>/NOTES.md`（agent 维护：结构怪癖、用户偏好、做过的改动、禁区）+ `history.jsonl`（程序追加：每次执行与写入的结果和错误码）；会话开始注入摘要；提供查看与清除入口；只存本地、不上传。
2. **禁区强制执行（Hooks 的工作簿版）**：记忆里标记的受保护表或区域，由 PreToolUse 在代码层拒绝写入，而不是只写在提示词里。
3. **知识技能（Skills 的工作簿版）**：自有 `load_skill(name, file)`（保持 `tools=[]`，不放开 CLI 内置工具），技能索引注入 system prompt 末尾，技能包由服务端下发并在本地缓存。首批：交付质量与验证、中文数据清洗（全半角、中文日期、万元单位、身份证/银行卡号被科学计数法吞掉、空值变体）、中文用户的公式写入（含 WPS 差异）、财务报表勾稽核对（中国会计准则口径）。随后：工资表与个税（累计预扣法，地区参数不写死）、考勤花名册、销售报表、应收账龄与对账、VBA 编写调试、WPS JSA。技能里的「常见报错」段由遥测聚合（工具名 × 错误码 × 次数）驱动更新。
4. **三种模式（权限模式的工作簿版）**：
   - **每步确认**：现有 M4 逐操作预览，默认模式。
   - **本次会话自动应用写入**：写入不再逐个弹确认，但每步都有检查点可回退；只在当前会话有效、不持久化（符合「允许并记住只适用于能力型授权」的约束）；删除表、VBA 等高风险操作仍然单独确认。
   - **只出方案**：agent 只读不写，产出变更计划（涉及的表和区域、每一步做什么、风险点），用户批准后按计划执行。
5. **副本试跑（M4 的升级）**：先 SaveCopyAs 出副本，由插件拉起隐藏的 Excel 进程打开（核对 PID）；代码先在副本上跑，返回改动、公式错误数前后对比、弹窗记录，用 ChangePreview 展示「试跑结果」；用户确认后在真实工作簿上**重放同一段代码**（强制备份），不把副本拷回去。副本期间订阅真实工作簿的 SheetChange / AfterSave，用户改过的区域与本次影响范围相交就提示重新试跑。副本 Excel 检测到启动 token 时不建任务窗格、不启动 sidecar、不报遥测。孤儿进程按 PID 加创建时间登记、启动时回收。外部链接、Power Query 等副本无法代表的场景在预览里明确标出。
6. **首次使用**：内置合成的中文示例工作簿 + 3 条示范问题；已有工作簿时基于结构理解给出「为你的文件推荐」；示例插入新表，不动用户文件。

## 执行护栏（贯穿各层，代码强制，不靠提示词）

- **VBA 编译前静态检查**（`Security/VbaStaticChecker.cs`）：公式字符串里的反斜杠转义与引号不配对、续行超过 24 个、`Option` 位置、模块级可执行语句、MsgBox / InputBox / `.Show`、没有出口的循环、修改 VBProject 自身。error 级问题直接退回给模型改。
- **VBA 执行期间的弹窗兜底**（`Executor/DialogGuard.cs`）：只看本进程的 `#32770` 对话框，询问类只点 No / Cancel、**绝不点 Yes**，提示类点 OK；点了什么如实回报。
- **执行前后保存并恢复应用状态**：ScreenUpdating、EnableEvents、Calculation、DisplayAlerts、StatusBar。
- **COM 瞬时错误有界重试**（仅 `0x80010001 / 0x8001010A / 0x800AC472`），硬错误附「下一步怎么修」的提示；同一错误连续 3 次时注入「换策略」提示。
- **VBA 字符串代码页安全**：当前代码页表示不了的字面量改写为 `ChrW()` 拼接。
- **Python 子进程**：Job Object 管整棵进程树、输出上限、超时时报出卡在哪一行。

## 模型、环境与可观测性

- **长上下文被提前压缩**（已完成）：实测 CLI 对非 Claude 模型一律按 200K 算、167K 时压缩，而 DeepSeek v4（flash / pro）的窗口是 1,048,576。侧车 `model_windows.py` 按实测窗口给模型名加 `[1m]`（CLI 发请求前会去掉，托管代理也会剥离），窗口小于 1M 或小于 200K 时再用 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 调到真实大小；只收录实测过的模型。托管模式下窗口可由服务端 EndpointConfig 的 `context_window` 给出，优先于内置表。
- **claude.exe 启动自检**：验证 `tools=[]` 时不依赖 Git Bash、老 Win10 上 ConPTY 可用；不满足时给出明确诊断码，而不是「没有回复」。
- **遥测落盘发件箱**：事件先写本地 `pending.jsonl`，上报成功再删；加载失败、sidecar 崩溃时由 C# 同步写文件；启动时补发。字段仍只走现有白名单。
- **trace_id 全链路**（部分放弃）：CLI 的自定义请求头（`ANTHROPIC_CUSTOM_HEADERS`）只能按进程设置，无法随任务变化；固定值会让服务端把整个会话算成一个任务。服务端已按请求形状判定新任务（F2），客户端不发 `x-trace-id`。
- **WPS 能否直接加载 Excel 的 VSTO 插件**（经 `Software\Kingsoft\Office\ET\AddinsWL` 白名单）：验证 CustomTaskPane 与 WebView2 是否可用。可行则两个宿主共用一套代码；结论出来前不改现有「WPS 保证不崩」的策略。

## 储备

- 工具面收敛：`write_range` v2（值、公式、格式、校验、合并、新建表合一，多区域一次事务一次备份，返回重算后的样本值和错误单元格）、`edit_structure`、`chart`、`pivot`、`run_macro`（按宿主只注册 VBA 或 JSA）；工具描述统一为「能力边界 / 何时用何时不用 / 返回值必须检查什么 / 失败后下一步」，返回值统一信封（`ok / status / checkpoint_id / next / warnings`）。
- 首条消息的结构化上下文信封（请求放最前 + 语言指令 + Excel 版本与动态数组支持 + 本轮检查点 id）；后续轮次只发请求本身，用 resume 代替 8000 字摘要；按宿主和模型动态组装 system prompt。
- 更新：文件租约替代进程名判断、Excel 退出时自动应用更新、启动回执 + 自动回滚；之后再做并排版本目录 + `current` 联接 + 只换 sidecar / UI 的小体积增量更新。
- 计费：按模型成本加权；托管模式由服务端下发模型目录（客户端只展示不判断）；额度用尽时「暂停任务、保住进度、充值后原地继续」；免费档只下发廉价模型并设成本硬上限；补齐增长漏斗事件。

- 隐私立场可见化：设置页「数据与隐私」，写明工作簿内容只发给你选择的模型、DeepExcel 不存储、遥测只含计数和版本，措辞与实现一致并有测试守卫。

## 明确不做

- 上传用户工作簿、完整对话轨迹或截图到云端。
- 放开 Bash / Read / Edit 等 CLI 内置工具，或随包附带便携 Git。
- 让 Python 经 COM 直接驱动**真实**工作簿（要做也只在副本上做）。
- 客户端自行选择辅助模型端点：需要时由服务端下发，BYOK 默认关闭。
- 商业授权的离线表格引擎；随机抽样。
- DCF / LBO / 并购 / PE / SOX 类技能：与国内目标用户距离太远，真有需求时由 M5 录制技能承接。
