# DeepExcel 改进路线（2026-09-25）

来源：对同类 Excel AI 插件做了一次全方位对照研究，并逐项核对了我们自己的代码。本文只记录**对 DeepExcel 的结论和要做的事**；对照研究的原始材料只留在本地，不入库。

人日按一名熟悉代码的工程师估算。【确认】= 已对照代码核实；【推断】= 需要真机复现。

---

## 核心判断

决定用户敢不敢把 AI 用在重要工作簿上的，是三件事：

1. **看得懂**：AI 每一步在干什么、哪一步失败了，用户能直接看到。现在面板只显示「已调用 N 个工具」和原始工具名，没有结果，也没有失败态。
2. **退得回**：改坏了能一键回到某一步之前。现在写入不自动备份，回退藏在历史弹窗里，而回滚本身还有丢数据的风险（见第 0 批）。
3. **读得准**：带标题行、多级表头、多个数据块的中国式报表不会被读错，公式的真实结构能被看到。

执行前变更预览（M4）、隐私白名单、更新签名、列级语义统计是我们已有的优势，路线里全部保留，并在其上补齐以上三点。

## 第 1 批：过程看得见（18–20 人日）

### 输出流

1. **统一事件信封**：sidecar 输出 `{"type":"ui_event","event":{...}}`，C# 与 WPS 宿主不解析内容、按 WorkbookKey 原样转给 UI；现有 `stream_delta / stream_end / tool_use / compacted` 逐步迁入。之后加任何展示事件只改 sidecar 和 UI 两处。（1.5）
2. **工具生命周期**：ToolUseBlock 发 `tool_start{tool_use_id, name, params}`；处理 ToolResultBlock 发 `tool_end{tool_use_id, is_error, brief, meta}`，只下发截断后的摘要字段。（2）
3. **中文文案目录**：`src/DeepExcel.UI/src/toolEvents/` 每个工具一份 start / done / fail 模板，变量来自参数和**结果**（done 文案只能用结果里的数字）；内部参数值要有中文映射。vitest lint 扫描 `excel_tools.py` 的 `@tool` 名单，断言每个工具都有目录项、模板变量都能填上。放在 UI 侧，Excel 与 WPS 共用一份。（3）
4. **叙事行**：用 `ToolStep` 取代「已调用 N 个工具」折叠组。每步一行：6px 状态点（运行中品牌色脉冲 / 完成绿 / 失败红）+ 一句人话；失败行默认展开错误摘要；连续多条已完成的只读步骤折叠成一行。参数与结果 JSON 只在开发者模式可见。（1.5）
5. **结构化错误**：异常改发 `error{error_kind, text}`，至少包括 `upstream_api_error / timeout / cancelled / internal`；UI 给出带下一步建议的一句话，并注明「已完成的修改会保留」；错误不再写进 assistant 历史。error_kind 以服务端返回为准，客户端不自己判断 BYOK / 托管。（1）
6. **防沉默看门狗**：模型 30 秒无流事件时显示「仍在等待模型服务」（原地更新秒数），150 秒放弃并按 F9 的流程隔离；工具级停滞也给状态提示。（2）

### 界面

7. **设计 token 层**：新建 `src/DeepExcel.UI/src/theme/tokens.css`，把 `styles.css` 里的硬编码颜色和未定义变量全部改成语义 token。基准值：品牌蓝 `#1A66D9`（白底对比 5.32:1）；冷灰中性色；信息性文字对比度 ≥ 4.5:1；字号 6 档（11 / 12 / 13 / 14 / 16 / 18）；4px 间距网格；圆角 4 / 6 / 8 / 12 / pill；阴影一律配真实 border；预留 dark 与 `forced-colors` 两套。（2–3）
8. **消息排版**：助手消息去掉气泡，改成全宽正文；用户气泡改浅中性底、不对称圆角；去掉每条的「你 / 助手」标签；复制等操作悬停时出现。（1）
9. **滚动与流式性能**：离底 60px 以上就停止自动跟随，并出现「回到底部」按钮；流式用 instant 滚动加 rAF 合帧；消息项 `React.memo` + 稳定 key。（1）
10. **顶栏瘦身 + 输入坞**：顶栏只留新建、历史、账户、更多；模型选择和附件移到输入框工具条；用容器查询保证 320px 不溢出（现在 320px 会裁掉 3 个按钮）。（1.5）
11. **检查点内联**：写入步骤成功后，工具行下挂「回到这一步之前」按钮，复用现有快照与回滚通道，tooltip 写清「之后的修改也会一起回退，回退前的版本会另存一份」。依赖 F1、F5。（1.5–3）

**验收**：非技术用户能看出每一步在做什么、失败在哪一步；面板不再出现无提示的长时间转圈；320 / 400 / 480px 三个宽度下界面都不溢出。

## 第 2 批：读得准 + 执行护栏（18–22 人日）

### 感知算法

分工原则：**取数靠宿主，算法放 Python 侧**。C# 与 WPS JS 只负责一次批量读出有界快照（`Value2` 网格、`FormulaR1C1` 网格、合并区列表，同一列连续相同的公式做游程编码），算法写在 `src/DeepExcel.Sidecar/perception/`，两个宿主共用，用 pytest 测试。WPS 由此首次获得与 Excel 相同的语义索引。

1. **区块检测**：非空掩码做 4 邻接 BFS 或并查集，合并单元格视为连通；丢弃被包含的孤岛；早停计数**不计已访问格**（避免漏掉大表下方的第二张表）；纵向只隔 1 个空行、列跨度重合 ≥ 80% 的两块合并；块数超过 25 时保留面积前 10 的块，其余只列范围。大表先用 `SpecialCells` 的 Areas 做矩形并查集加速，失败再退回网格 BFS。（C# 1 + WPS 1 + 算法 2）
2. **规则版多级表头**：对每个块的前 8 行逐行计算填充率、文本/数字/日期占比、横向合并与覆盖关系。先识别标题行，再识别最多 3 行表头，遇到数字或日期占比 ≥ 0.3 的行就停；数据首行往下 20 行类型稳定才采纳。列标签自底向上拼路径（如「扣款/养老/公司」）。拿不准时标「表头不确定」，由模型去实读。准备 20 个以上的黄金样例工作簿。（3–4）
3. **R1C1 公式模式**：按列求相同 R1C1 的游程，相邻列合并成矩形（不填洞），模式 id 取 R1C1 文本哈希；展示时用表头路径渲染（`RC[-2]*RC[-1]` → `[数量]*[单价]`）；每块最多列 5 条，同列出现多种模式时标「公式不一致」；扫描被截断时写「统计不完整」，不写数字。（3）
4. **（P1）保守的公式异常候选**：孤立偏离（上下 4 格一致而本格不同）、疑似被改成死值（列内公式占比 ≥ 90% 中的常量）、合计范围漏行、断链引用；排除合计/小计行、表头、合并格和动态数组；最多 20 条，只作候选、不自动修复。**AI 每次写公式后对受影响区域自动跑一遍**，结果接进变更预览。（3–4）
5. **（P1）覆盖诚实度**：采样得出的写「样本结论」，扫描截断时总数写 null；COM 读不到时明确告诉模型「沿用 N 分钟前的缓存」。（0.5–1）
6. **附件魔数嗅探**：xlsx 应以 `PK\x03\x04` 开头，xls 应以 `D0 CF 11 E0` 开头；都不是就直接提示「文件可能被企业加密软件保护，请在 Excel 中打开后再处理」，不要跑解析直到超时。快照一律走 SaveCopyAs（国内企业透明加密环境下，只有 Excel 进程能读到明文）。（0.5–1）

### 执行护栏

7. **VBA 编译前静态检查**（`Security/VbaStaticChecker.cs`）：只放高置信规则——公式字符串里的反斜杠转义与引号不配对、续行超过 24 个、`Option` 位置、模块级可执行语句、MsgBox / InputBox / `.Show`、没有出口的循环、修改 VBProject 自身。error 级问题直接返回给模型修改，不注入。（2）
8. **执行 VBA 期间的弹窗兜底**（`Executor/DialogGuard.cs`）：watcher 线程只看本进程的 `#32770` 对话框，询问类只点 No / Cancel、**绝不点 Yes**，提示类点 OK；点了什么如实回报给模型。（2–3）
9. **执行后工作簿体检**：执行前后统计公式错误单元格，检测新出现的外部链接（`LinkSources`）和引用不存在工作表的公式；有新增就在结果里标红并建议回滚。（1.5）
10. **执行前后保存并恢复应用状态**：ScreenUpdating、EnableEvents、Calculation、DisplayAlerts、StatusBar，只恢复到执行前的值。（0.5–1）

### 模型与环境

11. **长上下文被提前压缩**：非 Claude 模型可能在约 155K token 就被 CLI 压缩【推断】。修法（例如给模型名加窗口后缀）必须由服务端 EndpointConfig 决定，并在代理层剥离，客户端不自行判断。（1.5）
12. **claude.exe 启动自检**：在干净机器上验证 `tools=[]` 时不依赖 Git Bash；在老 Win10 上检查 ConPTY 导出。不满足时给出明确诊断码和指引，而不是「没有回复」。（1）

## 第 3 批：差异化（25–30 人日）

1. **副本试跑（M4 升级）**：先 SaveCopyAs 出副本，由插件自己拉起一个隐藏的 Excel 进程打开（核对 PID），代码先在副本上跑，返回改动、公式错误数前后对比和弹窗记录，用现有 ChangePreview 模型展示「试跑结果」；用户确认后在真实工作簿上**重放同一段代码**（强制备份），不把副本文件拷回去。关键改造：`IExcelActions` / `ToolDispatcher` 支持指定目标 Application / Workbook，这样所有现有工具都能 `target="lab"`。副本期间订阅真实工作簿的 SheetChange / AfterSave，用户改过的区域与本次代码影响范围相交就提示重新试跑。副本 Excel 检测到启动 token 时不建任务窗格、不启动 sidecar、不报遥测。孤儿进程按 PID 加创建时间登记、启动时回收。每个工作簿保留最近 20 个 checkpoint，关闭 7 天后清理。MVP 5–8 人日；外部链接、Power Query 等场景在预览里标明「副本无法代表」。
2. **知识技能**：自有 `load_skill(name, file)` 工具（不放开 CLI 内置工具），技能索引注入 system prompt 末尾，技能包由服务端下发并在本地缓存。首批四个：交付质量与验证、中文数据清洗（全角半角、中文日期、万元单位、身份证/银行卡号被科学计数法吞掉、空值变体）、中文用户的公式写入（含 WPS 差异）、财务报表勾稽核对（中国会计准则口径）。之后：工资表与个税（累计预扣法，地区参数不写死）、考勤花名册、销售报表、应收账龄与对账、VBA 编写调试、WPS JSA。技能里的「常见报错」段按月由遥测聚合（工具名 × 错误码 × 次数）驱动更新。（工具与下发 5 + 首批技能 8）
3. **首次使用引导**：内置合成的中文示例工作簿（销售明细、费用报销）+ 3 条示范问题；有工作簿时基于 M3 索引给出「为你的文件推荐」；插入示例用新表，不动用户文件。（4–5）
4. **按工作簿的记忆**：本地 `workbooks/<hash>/NOTES.md`（agent 写：怪癖、偏好、做过的改动）+ `history.jsonl`（程序写：每次执行和写入的结果与错误码）；会话开始注入最近摘要；提供「清除记忆」入口；只存本地、不上传。（3–4）
5. **运行中补充指令 + 计划胶囊**：运行中输入框不锁，补充内容排队，在下一次工具调用前经 PreToolUse 注入；多步任务在输入框上方显示进度胶囊（当前步骤 + 2/5 + 停止）。（3.5）
6. **隐私立场可见化**：设置页增加「数据与隐私」一节，写明工作簿内容只发给你选择的模型、DeepExcel 不存储、遥测只含计数和版本，并链接 `/api/v1/telemetry/schema`；措辞必须与实现一致，要有测试守卫。（0.5–1 + 法务）

## 并行：战略验证与可观测性（5–6 人日）

- **WPS 能否直接加载 Excel 的 VSTO 插件**（经 `Software\Kingsoft\Office\ET\AddinsWL` 白名单）：在 WPS 个人版和专业版里验证 CustomTaskPane 与 WebView2 是否可用。可行的话，WPS 与 Excel 可以共用一套宿主代码。只做验证，结论出来前不改现有「WPS 保证不崩」的策略。（1–2）
- **遥测改为落盘发件箱**：事件先追加写入本地 `pending.jsonl`，上报成功后再删；加载失败、sidecar 崩溃时由 C# 同步写文件；启动时后台补发。字段仍只走现有白名单。「装不上」「崩了」这两类最关键的信号，今天正是随进程退出一起丢掉的。（1.5–2）
- **trace_id 全链路**：C# 每个任务生成一个随机 trace_id 下发给 sidecar，用 contextvars 注入日志，调用代理时带 `x-trace-id`，服务端日志与遥测记录它。可与 F2 的 task_id 合并。（2）

## 储备（P1 / P2）

- 工具面 63 个 → 约 16 个：`write_range` v2（值、公式、格式、校验、合并、新建表合一，多区域一次事务一次备份，返回重算后的样本值和错误单元格）、`edit_structure`、`chart`、`pivot`、`run_macro`（按宿主只注册 VBA 或 JSA）、分层 `inspect_sheet`；工具描述统一为「能力边界 / 何时用何时不用 / 返回值必须检查什么 / 失败后下一步」，返回值统一信封（`ok / status / backup_id / next / warnings`）。8–12 人日，需做 A/B 评测。
- 首条消息的结构化上下文信封（请求放最前 + 语言指令 + Excel 版本与动态数组支持 + 本轮快照 id）；后续轮次只发请求本身，改用 resume 代替 8000 字摘要。
- 动态组装 system prompt（WPS 段 / 视觉段 / 模型补丁段）；「连续 3 次同一错误」时注入换策略提示；HRESULT → 修复提示映射；C# 侧 COM 瞬时错误有界重试。
- 更新：文件租约替代进程名判断、Excel 退出时自动应用更新、启动回执 + 自动回滚；之后再做并排版本目录 + `current` 联接 + 只换 sidecar / UI 的小体积增量更新。
